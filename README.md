# NUTZ · Forms

שני טפסים סטטיים, כל אחד קובץ HTML עצמאי אחד (פונטים, CSS ו-JS מוטמעים
בפנים — אפס תלויות חיצוניות, אין שלב build).

אתר Netlify: **nutz-forms.netlify.app**

## הלינקים לשליחה

| טופס | כתובת |
|---|---|
| גליון הרשמה | `https://nutz-forms.netlify.app/intake/form` |
| גליון הצהרת בריאות | `https://nutz-forms.netlify.app/health/form` |

הנתיבים באותיות קטנות. מי שיכתוב `/INTAKE/FORM` או סתם `/intake`
יופנה אוטומטית לכתובת הנכונה (ראה `public/_redirects`).

## מבנה

```
netlify.toml            הגדרות Netlify (publish = public)
apps-script/Code.gs     קוד השרת שכותב לגיליון (גיבוי; רץ בגוגל)
public/                 ← זו התיקייה שעולה לאוויר
  index.html            עמוד ריכוז עם קישור לשני הטפסים
  _redirects            הפניות מנתיבים חלופיים לנתיב הקנוני
  _headers              כותרות אבטחה
  robots.txt            חוסם אינדוקס בגוגל (מחק אם רוצים שיופיעו בחיפוש)
  intake/form/index.html   ← גליון הרשמה
  health/form/index.html   ← גליון הצהרת בריאות
```

## איך מעלים

**דרך 1 — גרירה (הכי מהיר):**
נכנסים ל-[app.netlify.com/drop](https://app.netlify.com/drop) וגוררים
את התיקייה **`public`** (לא את `FORMS`). זהו.

**דרך 2 — Git:**
מחברים את הריפו ל-Netlify. ה-`netlify.toml` כבר מגדיר `publish = "public"`
ו-`command = ""`, אז אין מה להגדיר ידנית.

## עדכון טופס

עורכים ישירות את `public/intake/form/index.html` או
`public/health/form/index.html` ומעלים מחדש. אין קובץ מקור נפרד.

## שליחת הטפסים

בראש הסקריפט בכל טופס יש בלוק `CONFIG`:

```js
const CONFIG = {
  ENDPOINT: "https://script.google.com/macros/s/.../exec",  // Web App של Apps Script
  WHATSAPP: "972509007640",
  SOURCE:   "הצהרת בריאות"
};
```

כל הגשה עושה שני דברים: נכתבת לגיליון Google Sheets, ונפתחת כהודעת
WhatsApp לליאב. אם `ENDPOINT` ריק — רק ה-WhatsApp עובד.

`SOURCE` היא התווית שנכתבת בעמודת "מקור". היא נשארה בערכיה הישנים
(`שאלון קבלה`, `הצהרת בריאות`) בכוונה, כדי לא לפצל את הנתונים
ההיסטוריים בגיליון כששמות הטפסים השתנו.

## הגיליון וה-Apps Script

שלושה מקורות כותבים לאותו קובץ Sheets, כל אחד ללשונית משלו:

| מקור | לשונית |
|---|---|
| דפי הנחיתה | הלשונית הראשונה (הלידים הקיימים) |
| גליון הרשמה | `גליון הרשמה` |
| גליון הצהרת בריאות | `גליון הצהרת בריאות` |

שתי הלשוניות של הטפסים נוצרות אוטומטית בהגשה הראשונה, עם שורת כותרות.

קוד השרת נמצא ב-`apps-script/Code.gs`. הוא שמור כאן כמקור-אמת; העותק
שרץ בפועל יושב בעורך ה-Apps Script של הגיליון (בפרויקט בשם
"חיבור טבלת לידים לאתר"). מגיעים אליו מהגיליון: תוספים ← Apps Script.

**עדכנת את הקוד כאן? הדבק אותו גם שם, אחרת השניים מתפצלים.**

### שישה באגים שהקובץ הזה תיקן

1. `getActiveSheet()` הוחלף בהפניה מפורשת ללשונית הראשונה.
   `getActiveSheet` מחזיר את הלשונית ה*פעילה*, ו-`insertSheet` הופך
   לשונית חדשה לפעילה — כלומר יצירת הלשוניות החדשות הייתה עלולה
   להסיט לידים מדפי הנחיתה ללשונית הלא נכונה.
2. לשוניות חדשות נוצרות בסוף (`insertSheet(name, getNumSheets())`),
   כדי שלשונית הלידים תישאר ראשונה.
3. עמודות ת״ז, טלפון, תאריך וחתימה מסומנות כטקסט (`setNumberFormat('@')`).
   בלי זה Sheets מפרש `012345678` כמספר ומוחק את האפס המוביל — ת״ז
   שגויה בהצהרת בריאות, שהיא מסמך משפטי לפי חוק הספורט. הרשימה
   נמצאת ב-`TEXT_KEYS`. הפורמט מוחל ביצירת הלשונית; ללשוניות שכבר
   קיימות יש `nutzApplyTextFormats()`. הוא מתקן את ההמשך ולא משחזר
   ערכים שכבר נפגעו.
4. הכתיבה עוברת דרך `appendRow_` ולא דרך `sheet.appendRow`. האחרון
   לא מכבד באופן עקבי פורמט שהוגדר מראש על הטווח, ועלול להמיר את
   הערך תוך כדי הכתיבה. `appendRow_` מסמן את התא הספציפי כטקסט
   רגע לפני `setValues`.
5. `textColumnIndexes_` מאתר את עמודות הטקסט לפי שם הכותרת בגיליון,
   לא לפי מיקומן במערך שבקוד — עקבי עם `buildRow_`, שעובד כך ממילא.

6. גם הטלפון בלשונית `לידים` נשמר כטקסט. הבעיה הייתה שם מאז ומתמיד
   ולא הגיעה מהטפסים — `0525088443` נשמר כ-`525088443`. `handleLanding_`
   מסמן את התא כטקסט לפני הכתיבה, ו-`nutzRepairLandingPhones()` מתקן
   שורות קיימות. הוא מתקן רק מה שחד-משמעי (בדיוק תשע ספרות שמתחילות
   ב-5), ומדפיס ליומן את מה שדילג עליו לבדיקה ידנית.

   `handleLanding_` עבר מ-`appendRow` ל-`setValues`. `setValues` קורס על
   `undefined`, ולכן כל שדה חסר מומר למחרוזת ריקה — ארבעת דפי הנחיתה
   לא כולם שולחים את אותם שדות.

### למה צריך שתי צורות קריאה

דפי הנחיתה שולחים JSON גולמי, ונקראים ב-`e.postData.contents`.
הטפסים כאן שולחים POST של טופס בתוך iframe, ונקרא ב-`e.parameter.payload`.
`parseBody_` מטפל בשתי הצורות, כך שאף צד לא צריך להשתנות.

### שמירת ההצהרה ל-Drive

כל הגשה של הצהרת בריאות נשמרת גם כקובץ PDF בתיקייה
`NUTZ · הצהרות בריאות` ב-Drive של **בעל הסקריפט**.

למה זה נחוץ: כפתור ההורדה שבטופס הוא `window.print()` של הדפדפן —
הקובץ נוצר אצל המתאמן ונשאר אצלו. מי שסוגר את הלשונית בלי ללחוץ
עליו לא משאיר לליאב שום מסמך, רק שורה בגיליון. בהצהרת בריאות,
שהיא מסמך משפטי לפי חוק הספורט, זה פער.

איך: `exportDocHtml()` בטופס לוכד את אלמנט `#doc` כ-HTML עצמאי
ושולח אותו בשדה `docHtml`. `saveDeclarationPdf_` ממיר אותו ל-PDF
ושומר. נלכד בדיוק אותו אלמנט שהמתאמן רואה ומוריד, ולכן אין שתי
גרסאות עיצוב שעלולות להתפצל.

`docHtml` **אינו נכתב לגיליון** — אין לו כותרת ב-`HEALTH_COLUMNS`,
ו-`buildRow_` כותב רק עמודות שיש להן כותרת.

שלושה דברים שהיו נשברים בהמרה, ומטופלים ב-`exportDocHtml`:

| | הבעיה | הפתרון |
|---|---|---|
| פונטים | מוטמעים כ-base64, לא נטענים בצד גוגל | `--display`/`--body` נדרסים למחסנית מערכת |
| לוגו | webp, לא נתמך בהמרה | מצויר לקנבס ומיוצא כ-PNG |
| רוחב | `#doc` גולש והטקסט נחתך בקצה | `width:186mm` — שטח ההדפסה של A4 |

בנוסף, `buildDoc()` הוזז לרוץ **לפני** השליחה. קודם הוא רץ אחריה,
כלומר ברגע הלכידה המסמך עדיין היה ריק מתוכן.

**פרטיות:** התיקייה מכילה תעודות זהות ומידע רפואי. היא פרטית
כברירת מחדל — אל תשתף אותה בהרחבה.

**ידוע ולא נבדק:** ההמרה של Apps Script מ-HTML ל-PDF בסיסית.
המסמך אומת שהוא מרנדר נכון ב-Chrome, אבל מנוע ההמרה של גוגל שונה.
בדוק את ה-PDF הראשון שנוצר בפועל לפני שסומכים על זה.

### הרשאות (appsscript.json)

`DriveApp` דורש הרשאה שהסקריפט לא קיבל בהרשאה המקורית, שכיסתה
Sheets בלבד. Apps Script מזהה הרשאות בסריקה סטטית, אבל אסימון
קיים לא מתרחב מעצמו כשמוסיפים API חדש. התוצאה:

```
You do not have permission to call DriveApp.getFoldersByName
```

`apps-script/appsscript.json` מצהיר על ההרשאות במפורש ומאלץ מסך
אישור חדש. להצגתו בעורך: הגדרות הפרויקט ← סמן "הצגת קובץ המניפסט
appsscript.json בעורך".

| הרשאה | למה |
|---|---|
| `spreadsheets.currentonly` | גישה לגיליון שהסקריפט מקושר אליו בלבד |
| `drive` | `getFoldersByName` ו-`createFolder` דורשים אותה |

`drive` היא הרשאה רחבה. `drive.file`, שנותנת גישה רק לקבצים
שהסקריפט יצר, לא מספיקה — איתור תיקייה קיימת דורש הרשאת קריאה רחבה.

### התקנה

1. בעורך ה-Apps Script: סמן הכל, מחק, הדבק את `apps-script/Code.gs`, שמור.
2. הרץ פעם אחת את `nutzSelfTest` ואשר הרשאות.
3. לפריסה ← ניהול פריסות ← עיפרון ← גרסה: **New version** ← פריסה.
   `New version` ולא פריסה חדשה, אחרת כתובת ה-exec משתנה ודפי הנחיתה נשברים.

### ידוע ולא טופל

דפי הנחיתה שולחים שדה `משפך` (הערך `דף נחיתה`), אבל הוא לא נכתב
לגיליון — לא בקוד הקודם ולא בנוכחי, כדי לא לשנות את מבנה העמודות
הקיים. אם תרצה אותו כעמודה, צריך להוסיף אותה ללשונית ולקוד יחד.
